## 页面与使用流程

- `/games`：互动课程入口，按名称与说明即时搜索，包含 KNN 采集入口。
- `/games/knn`：列出已安排且尚未到截止时间的批次；草稿和手动关闭的批次不列出。
- `/games/knn/:batchId`：学生使用教师分享的批次链接，核对学号、填写、确认后提交。
- `/admin/it-technology?view=knn`：教师管理入口，保留在信息技术应用管理内部。

教师点击后台“信息技术”菜单直接进入 KNN 视图；带 `batch` 的直链与刷新保留所选批次。
教师仅可访问 `view=knn`，应用目录、开关和 ML 等其他编辑器仍遵循原管理员权限；学生不能进入管理视图。
教师工作区的返回动作前往管理首页，管理员则返回 IT 应用目录。

学生无需登录，只填写教师名单中的学号，不收集姓名或班级。学号用于课堂登记与防止重复提交，
不验证填写者的真实身份。公开接口只返回批次信息与所查询学号的提交资格，不返回名单或答案。
学生草稿仅保存在当前浏览器会话中；成功提交后清除草稿，共用设备可通过“换一位同学”重新填写。

教师创建批次时默认生成 `1..65` 学号，可按实际人数生成或粘贴名单。教师设置起止时间，
随后选择按时开放或立即开始；也可提前结束。管理工作区显示应交、已交、未交、待重填人数，
支持查看未交学号、搜索名单、查看当前答案与历史、授权或撤销重填、导出 CSV 与冻结课堂 JSON。

信息技术应用管理采用无外框、无分割底栏的嵌入式紧凑卡片，按“公开课”“课堂工具”“AI 与编程”“游戏与资源”分组；公开课依次包含“召唤一名AI同学”“密码锁破解”“KNN 运动习惯采集”。
KNN 采集的开放状态由批次控制，不创建额外的功能开关。

## 采集字段

固定采集六类运动习惯，每类包含过去一周参与天数 `0..7` 与喜欢程度 `0..4`：

| 顺序 | 类别 | 学生提示示例 |
|---|---|---|
| 1 | 球类对抗 | 篮球、足球、乒乓球、羽毛球 |
| 2 | 力量 | 俯卧撑、仰卧起坐、深蹲 |
| 3 | 耐力 | 慢跑、游泳、骑行 |
| 4 | 技巧 | 跳绳、体操、舞蹈 |
| 5 | 团队配合 | 接力、合作游戏、团队球赛 |
| 6 | 日常活动 | 步行、爬楼梯、课间活动 |

`features` 固定为 12 个整数，依次按上述类别交替保存 `[天数, 喜欢程度, ...]`。
喜欢程度编码为：`0` 完全不喜欢、`1` 不太喜欢、`2` 一般、`3` 比较喜欢、`4` 非常喜欢。
不接受布尔值、数字字符串或未填写值替代整数。

学生填写时，参与天数 `0–7` 与五档喜欢程度全部展开为可直接点击的单选项，不使用下拉菜单；
每组只选一个值，初始不预选，支持键盘切换，窄屏保留完整选项并调整文字排列。

另收集运动意向 `label`，只允许“球类对抗”“力量类”“耐力类”“技巧类”。它是课堂分类标签，
不拼入特征向量。`display_consent` 默认 `false`，仅表示愿意作为匿名学生 A 展示，
与允许采集答案分开处理；其他学生仍可作为匿名样本进入教师冻结的课堂数据。

## 时间、学号与提交规则

- 时间必须包含时区，截止时间严格晚于开始时间；服务器在每次新提交时判断 `开始 <= 当前 < 截止`。
- 持久状态为 `draft`、`scheduled`、`closed`；展示阶段额外根据服务器时间推导 `open` 和 `ended`。
  草稿、待开始、已到期和手动关闭阶段均拒绝新提交。立即开始会把开始时间改为服务器当前时间。
- 每批名单为 `1..1000` 人，学号为 `1..24` 位字母、数字、下划线或短横线，首位须为字母或数字。
  去除首尾空格后，纯数字学号忽略前导零，字母忽略大小写，因此 `01` 与 `1`、`a01` 与 `A01`
  各视为同一学号；`A01` 与 `A1` 保持不同。名单中的规范化重复会被拒绝。
- 同一批次同一学号默认只提交一次。客户端提交带 `expected_revision` 和 UUID `request_id`；
  状态已变化、已提交且未获重填授权时返回冲突，不能通过重复点击覆盖答案。
- 同一请求凭证与相同内容重试返回原回执，即使批次随后结束；凭证已使用但内容不同则拒绝。
  重放旧成功请求不会消耗新获得的重填机会。
- 重填授权只适用于已提交学号，每次允许新增一个版本；成功后自动消耗授权。等待重填时，
  旧版本仍计为已交且仍是有效答案。撤销授权不会删除旧答案。
- 已提交学号不能从名单移除。只允许删除尚无提交的草稿批次，防止通过管理界面误删采集历史。

教师只能管理自己创建的批次；`admin`、`super_admin` 可管理所有批次。管理 API 复用
`require_staff` 和既有会话认证，不使用原型的公开教师接口或 JSON 文件存储。

## 导出与冻结

CSV 导出包含名单全部学号、未交状态、当前版本、重填授权、12 维特征、意向、匿名展示选择及
提交时间。CSV 使用 UTF-8 BOM，学号以公式危险字符开头时加转义前缀；历史版本由历史接口查看。

冻结至少需要 4 份有效答案，并选择一位已同意匿名展示的学生 A；未指定时按名单顺序选择首位符合者。
冻结结果是独立快照，之后提交、重填、修改名单或时间不会更新它。每批只能冻结一次，重复冻结返回
`409`，已冻结结果可重复下载。

```json
{
  "version": 1,
  "aId": "S01",
  "students": [
    { "id": "S01", "label": "耐力类", "features": [1, 2, 1, 2, 4, 4, 1, 2, 2, 3, 6, 4] }
  ]
}
```

以上仅展示结构，真实冻结结果至少包含 4 位学生。匿名 ID 按当次有效答案的名单顺序生成，
JSON 不含学号、提交时间或重填记录。此功能准备课堂数据，不执行 KNN 训练、距离计算或预测。

## 数据模型与迁移

正式结构通过 Alembic revision `20261020_0001` 新增，前置 revision 为 `f1a2b3c4d5e6`：

| 表 | 职责与主要约束 |
|---|---|
| `it_knn_batches` | UUID 批次、创建者、带时区时间窗、状态、冻结 JSON 与冻结时间；校验合法状态及时间顺序 |
| `it_knn_roster` | 批次名单、展示学号与规范键、顺序、当前版本、重填授权；`(batch_id, student_key)` 唯一 |
| `it_knn_submissions` | 不可覆盖的答案版本、请求凭证、内容摘要及提交时间；`(roster_id, revision)` 与 `(roster_id, request_id)` 唯一 |

创建者引用 `sys_users.id`，删除用户时设空；名单引用批次、答案引用名单，采用级联外键。
已有批次的提交、配置、重填与冻结写入均锁定批次行，在同一事务内裁决，异常时回滚。
新表与既有问卷、课堂、AI伙伴表独立，不回填或改写现有业务数据。

迁移应先在隔离 PostgreSQL 验证升级、降级、再次升级及并发约束，再在目标环境执行。
降级会删除这三张表及其采集、历史和冻结数据，不能用于有业务数据时的无损回滚；
目标环境迁移前按[部署指南](../docker/deploy/DEPLOY.md)备份数据库。
仅改源码或开发环境迁移，不代表服务器完成升级。
