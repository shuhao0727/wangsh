## 三、安全与合规分析

### 3.1 安全风险清单（按严重程度）

#### 🔴 P0 - 严重风险（3 个）

**1. 横向越权漏洞**
- **问题**：`session_id` 枚举可访问他人对话
- **位置**：`conversations.py::get_conversation()`
- **影响**：学生可查看其他学生对话
- **修复**：
```python
# 验证 session_id 所有权
stmt = select(ZntConversation).where(
    and_(
        ZntConversation.session_id == session_id,
        ZntConversation.user_id == user_id
    )
).limit(1)
if not (await db.execute(stmt)).scalar_one_or_none():
    raise HTTPException(403, "无权访问该会话")
```

**2. API Key 泄露风险**
- **问题**：
  - SSE Query Token 出现在 URL/日志
  - 加密密钥管理不当
  - Provider 日志可能记录完整 Key
- **修复**：
  - 禁用 SSE Query Token，改用 POST + EventStream
  - 实施密钥轮换机制
  - 严格日志脱敏

**3. 对话内容明文存储**
- **问题**：`znt_conversations.content` 无加密，学生隐私数据暴露
- **影响**：数据库泄露后所有对话可读
- **修复**：
```python
class ConversationEncryption:
    def encrypt(self, content: str) -> str:
        return self.cipher.encrypt(content.encode()).decode()
```

#### 🟠 P1 - 高风险（4 个）

**4. XSS 漏洞**
- **问题**：用户输入未过滤 HTML/Script 标签
- **修复**：
```python
from html import escape

@field_validator("description", "system_prompt")
def sanitize_html(cls, v):
    return escape(v) if v else v
```

**5. Prompt Injection**
- **问题**：恶意用户可操控 AI 行为
- **修复**：
```python
FORBIDDEN_PATTERNS = [
    r"ignore\s+(previous|above|all)\s+instructions?",
    r"system\s*:\s*you\s+are",
]
```

**6. GDPR 违规**
- **问题**：
  - ❌ 缺少数据导出接口
  - ❌ 缺少被遗忘权实现
  - ❌ 缺少数据处理同意记录
- **修复**：
```python
@router.get("/me/export")
async def export_my_data(current_user, db):
    # 导出用户所有数据
    pass

@router.delete("/me/data")
async def delete_my_data(current_user, db):
    # 硬删除 + 审计日志
    pass
```

**7. CSRF 漏洞**
- **问题**：状态变更接口无 Token 保护
- **修复**：
```python
from fastapi_csrf_protect import CsrfProtect

@router.post("/agents")
async def create_agent(csrf_protect: CsrfProtect = Depends()):
    await csrf_protect.validate_csrf(request)
```

#### 🟡 P2 - 中风险（4 个）

8. **限流不足**：缺少细粒度限流
9. **审计日志缺失**：敏感操作未完整记录
10. **错误信息泄露**：Provider 错误详情可能泄露内部信息
11. **加密密钥无轮换**：长期使用同一密钥风险高

### 3.2 合规缺口

| 合规项 | 状态 | 缺口 |
|--------|------|------|
| GDPR 数据导出 | ❌ | 用户无法导出自己的对话 |
| GDPR 被遗忘权 | ❌ | 无法彻底删除用户数据 |
| 数据处理同意 | ❌ | 未记录用户同意状态 |
| 审计日志 | ⚠️ | 仅记录 CRUD，未记录查看/导出 |

## 四、性能与可扩展性分析

### 4.1 性能瓶颈识别

#### CPU 密集型瓶颈

**热点分析服务**（`agent_hot_analysis.py`, 796 行）
- **贪心聚类算法**：O(n²) 时间复杂度
- **jieba 分词**：GIL 限制，无法利用多核
- **现象**：1000+ 事件时响应 &gt; 10s
- **影响**：阻塞 Web Worker，影响其他请求
- **方案**：移至 Celery 异步任务 + 进度通知

#### I/O 密集型瓶颈

**数据库查询**
- **缺少核心索引**：
  ```sql
  -- 缺失的 5 个关键索引
  ix_conversations_session_created (session_id, created_at DESC)
  ix_conversations_agent_time (agent_id, created_at)
  ix_group_messages_session_created (session_id, created_at DESC)
  ix_conversations_user_agent_time (user_id, agent_id, created_at DESC)
  ix_users_class_name (class_name)
  ```
- **查询性能**：100-500ms（应优化到 10-50ms）

**Provider API 调用**
- **Dify 租约**：获取延迟 ~200ms
- **流式响应**：长时间占用连接
- **无请求合并**：相同查询重复调用

**Redis 操作**
- **Dify 并发租约**：高频 Lua 脚本执行
- **缓存穿透风险**：失效时可能导致数据库压力

### 4.2 并发能力评估

| 维度 | 当前能力 | 瓶颈 | 优化后预期 |
|------|---------|------|-----------|
| **单实例并发** | 20-40 | 数据库连接池 + Dify 租约 | 100+ |
| **Dify 智能体** | 20 | 全局租约限制 | 50 (动态调整) |
| **非 Dify** | 40 | 数据库连接池 | 200 (连接池扩容) |
| **热点分析** | 1 (同步) | CPU 阻塞 | 10 (Celery 并发) |
| **水平扩展** | 2-3x | 数据库单主 | 5-10x (读写分离) |

### 4.3 可扩展性设计

**✅ 优点**：
- 无状态设计（智能体缓存使用 TTL）
- Dify 租约通过 Redis 共享，支持多实例

**⚠️ 问题**：
- 熔断器状态不跨进程（可能导致雪崩）
- 数据库单主架构，写入无法水平扩展
- 分析结果大 JSON 字段拖慢主库

**扩展评分**：🟡 中等（可以水平扩展 API workers，但数据库和 Dify 是瓶颈）

### 4.4 性能优化空间

| 优化项 | 当前 | 优化后 | 改进幅度 | 实施成本 |
|--------|------|--------|---------|---------|
| 添加核心索引 | 100-500ms | 10-50ms | 5-10x | 2 小时 |
| 会话列表缓存 | 100-500ms | 10ms | 10-50x | 4 小时 |
| 深度分析异步化 | 5-30s 阻塞 | 100ms | 即时响应 | 2 天 |
| 分析结果缓存 | 秒级 | 10ms | 100x+ | 4 小时 |
| 熔断器 Redis 化 | 不共享 | 共享 | 可用性 +30% | 1 天 |
