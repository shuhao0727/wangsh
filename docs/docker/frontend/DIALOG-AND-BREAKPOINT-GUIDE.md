# 前端对话框宽度与响应式断点规范

> 状态：reference
> Owner：frontend
> 最近复核：2026-10-04

本文记录对话框宽度档位与 PC 分辨率适配的**实测现状**与推荐做法。
2026-10-04 抢救自已删除的 `PC_MULTI_RESOLUTION_REPORT.md` §4.1/§2.1，
但**已剔除该报告的计算值与过期数据**（其复选框全部未勾选、自述"代码审查 + 组件分析"，
不含真实视口实测）。下列宽度分布均为当日 `rg` 实测。

---

## 一、对话框宽度现状

`frontend/src/components/ui/dialog.tsx` 的 `DialogContent` 默认 `max-w-lg`
（Tailwind `max-w-lg` = 32rem = **512px**），调用方通过 `sm:max-w-[Npx]` 覆盖。

实测全项目 `max-w-[Npx]` 分布（含非对话框用法）：

| 宽度 | 出现次数 | 典型用途 |
|------|---------|---------|
| 640px | 11 | 中等表单、分类管理（`CategoryManageModal`） |
| 780px | 9 | 复杂表单、题目编辑（`QuestionsPage`） |
| 480px | 8 | 简单确认、轻量编辑 |
| 1100px | 6 | 大编辑器、样式管理（`MarkdownStyleManagerModal`） |
| 420px | 5 | 小型提示 |
| 680px | 4 | 中等表单 |
| 400px | 3 | 紧凑弹窗（`MindmapGallery`） |

> 其余 `220px`/`160px`/`96px` 等小值为下拉、徽标等非对话框元素。

### 1.1 推荐档位

避免继续引入任意像素值，新增对话框请归入以下四档之一：

| 档位 | 宽度 | 适用 |
|------|------|------|
| 小 | 400–520px | 确认、提示、单字段编辑 |
| 中 | 560–720px | 常规表单（3–8 字段） |
| 大 | 780–1000px | 复杂表单、列表选择 |
| 超大 | 1100px+ | 富编辑器、样式/配置管理 |

现有值 `480`/`640`/`780`/`1100` 已落在档位内；新增时优先复用这四个值，
而不是再取新数字。

## 二、响应式断点现状

**项目未配置自定义 Tailwind `screens`**（`tailwind.config.js` 无 `screens` 键），
因此 `sm/md/lg/xl/2xl` 全部是 Tailwind 默认断点。

超宽屏适配走 **CSS 媒体查询**，位于 `frontend/src/styles/index.css`：

| 断点 | 位置 | 用途 |
|------|------|------|
| `max-width: 640px` | L687 | 窄屏收敛 |
| `max-width: 768px` | L567 | 移动端 |
| `min-width: 640px` | L770 | 平板及以上 |
| `min-width: 769px` | L575 | 桌面 |
| `min-width: 1024px` | L776 | 大屏 |
| `min-width: 1366px` | L579 | 笔记本/标准桌面 |
| `min-width: 1920px` | L585 | 全高清 |
| `min-width: 2560px` | L591 | 2K/超宽 |

### 2.1 已知缺口

- **`1440px`、`1600px` 无专门断点**：1440p 与 1600p 显示器在 1366 与 1920 之间，
  目前只继承 1366 档规则。
- **`3440px`（21:9 带鱼屏）无断点**：`xl:` 仅 3 处、`2xl:` **0 处**，
  超宽屏布局主要靠 `--ws-shell-max-width` 限宽而非断点。

### 2.2 适配原则

1. **推广现有机制，不新建断点体系**。曾提出过 `laptop/desktop/wide/ultra`
   自定义断点，与上述 CSS 媒体查询 + `--ws-shell-max-width` 双轨冲突，**已废弃**。
2. 超宽屏优先用**限宽**（`--ws-shell-max-width`）而非新增栅格断点，
   避免内容被过度拉伸。
3. 侧边栏宽度以 `--ws-sidebar-width: 216px` 为准
   （旧报告写的 240/280/320px **已过期，勿引用**）。

## 三、验证方法

### 3.1 侧边栏占比核算（可复用方法）

旧报告用「侧边栏宽度 ÷ 视口宽度」核算占比，方法本身可复用，但**须用当前值重算**：

| 视口 | 侧边栏占比（216px） |
|------|-------------------|
| 1366px | 15.8% |
| 1920px | 11.25% |
| 2560px | 8.4% |

占比过高（> 20%）说明侧边栏需折叠或收窄。

### 3.2 视口清单

回归至少覆盖 4 档；有超宽屏需求时补后两档：

| 档位 | 分辨率 | 对应现状 |
|------|--------|---------|
| 笔记本 | 1366×768 | 有断点 |
| 标准桌面 | 1440×900 / 1600×900 | **无断点（缺口）** |
| 桌面 | 1920×1080 | 有断点 |
| 2K | 2560×1440 | 有断点 |
| 超宽 | 3440×1440 | **无断点（缺口）** |
