# 文档维护与归属规范

> 状态：active
> Owner：docs
> 最近复核：2026-10-31
> 复核周期：每 90 天

本文规定文件归属、整理、删除和更新方法，供开发者与 AI 协作使用；操作授权见 `CLAUDE.md`。

## 核心原则

- 一个主题一个维护来源。入口负责导航，操作指南负责步骤，参考文档负责合同，历史记录负责追溯。
- 先写读者要做的事和适用条件，再给必要步骤；合并重复说明，不用口号、事故故事或旧统计撑篇幅。
- 精简不能删掉唯一的接口参数、权限限制、恢复步骤或验收证据。操作命令对照当前脚本；尚未核准的内容明确标注。
- 当前行为写 owner 文档，未来动作写计划，实测结果写测试状态，历史过程保留原日期与范围。
- 先更新已有文件；只有主题确实独立才新增，不制造平行规范或“最终版”。

## 目录与生命周期

- `docs/` 根层只放总索引和文档规则；按功能、开发、运维、测试、界面、计划、安全隐私、归档分类，职责见[总索引](README.md#目录框架)。
- `plans/` 只留当前计划和统一台账；旧计划归档前，将未结事项、来源及关闭条件承接到当前台账。
- `testing/TEST_STATUS.md` 保持一页左右，只写当前基线、最近结果、缺口和证据入口；完整批次按日期或版本存入 `archive/testing/`。
- `archive/` 按主题保留历史，主索引直接链接每份归档；索引可为 `active`，历史正文标记 `archived`。
- 模块说明就近维护，一次性排查材料放仓库外临时目录；迁移完成后删除无实际引用的旧跳转。已退出的 `docs/docker/` 不重建，运维文档统一放 `operations/`。
- 计划、治理、报告在顶部注明状态、Owner、复核日期；被替代或归档时补目标和条件。
- Owner 表示维护职责；开始执行时指定实际执行者，同一文件同一时段由一人汇总编辑。

| 状态 | 用途 |
|---|---|
| `active` | 当前依据，随相关改动更新 |
| `reference` | 稳定参考，不持续复制动态结果 |
| `superseded` | 已被替代，保留替代入口与归档条件 |
| `archived` | 只供追溯，进入 archive 并更新索引 |
| `redirect` | 仅为真实旧引用保留；不超过 25 行，说明状态与目标 |

`active` 每 90 天、`reference` 每 180 天复核；相关行为变化时立即复核，不能等到周期结束。
复核日期只在实际检查相应内容后更新；局部复核写明范围。超期表示待复核，不是自动失效或删除依据。
归档不定期重验业务；发现错误时追加有日期的订正，保留原结论和依据。

## 命名与新增

- 稳定指南使用稳定主题名；沿用现有名称。新增普通文档用小写英文短横线，固定入口保留 `README.md`、`CLAUDE.md` 等名称；不为统一大小写批量改名。
- 日期型证据用 `YYYY-MM-DD-topic.md`；同日同主题追加到已有批次，不生成 `final`、`latest`、`v2-final` 或重复总结。
- 新增前查 owner 与同主题内容；能补一节就不另开文档。独立长流程才建专项指南/计划，并从所属索引或台账链接。
- 根层保留上手、协作和必要配置；模块说明、长期测试和脚本就近存放。截图、探针、草稿默认放仓库外 scratch，文件名体现任务与日期。
- 文档只记理解或操作所需内容；接口细节、步骤、动态结果各归其 owner，其他位置引用，不复制整段。

## 整理、移动与归档

1. 先列本批准确路径与动作，核对分支、已有修改、用途和内容来源；按主题小批处理。
2. 合并时保留唯一的约束、反例、权限、恢复步骤、失败证据和未结事项；不能只比较标题或修改时间。
3. 未结项先进入当前台账，保留原编号、证据日期、owner 与关闭条件；合并、归档不等于解决。
4. 移动后同步实际受影响的索引、Markdown 链接/锚点、源码注释、脚本和 workflow 引用。除路径外不借机改历史正文。
5. 旧路径确有外部引用或迁移窗口时才留 redirect，写明目标和退出条件；无法核实外部引用时说明限制，不宣称“完全无引用”。
6. 回读目标文件，对照原文核对独有内容和引用。任务结束前给出实际改动与验证结果，不以目录变整齐代替保真。

迁移、归档和删除分别记录。Git 中旧路径 `D` 加新路径未跟踪不等于内容被删除；先核对目标与正文。
跨目录重组在已有索引或批次记录保留旧新路径对照及基线；迁移项不重复记为退出删除。

## 删除规范

“旧”“重复”“没有搜索结果”只表示候选。删除须在授权范围内，逐项满足以下条件：

1. **对象明确**：确认准确路径、文件类型和符号链接目标，核对未提交/未跟踪内容与其他任务占用；涉及运行目录、脚本、配置或数据时另核运行进程及挂载。
2. **用途查清**：搜索入链、导入、动态加载、命令、配置与发布/恢复流程。静态搜索不能证明没有外部调用；疑点未消除先保留。
3. **内容承接**：有效说明已有可定位替代，或功能已明确退役；独有历史、失败证据和未结项有承接入口。
4. **恢复真实**：Git 恢复须核实具体提交和原路径确实含待删内容。未提交、未跟踪或忽略文件不能声称由 Git 保全；必要时保存仓库外定向快照并核对哈希。不要每次机械复制全仓。
5. **引用同步**：先改调用方、索引和替代入口，再小批删除。删除文档记入现有归档索引，删除脚本记入脚本退出索引；记录旧路径、理由、替代、日期和恢复来源。
6. **结果验收**：重查旧引用、差异与相关验证，确认没有扩大删除范围；不能因链接检查通过就关闭源码、数据或部署验收。

| 对象 | 额外要求 |
|---|---|
| 重复文档、旧计划 | 对照全文；保留唯一决策、反证与未结项，再决定合并、归档或删除 |
| 源码、长期测试、脚本 | 核对导入、路由、npm 命令、CI、smoke 编排及兼容入口；验证替代行为或已确认的退役范围 |
| SQL、迁移、部署和回滚资料 | 核对 Alembic 覆盖、执行历史与恢复链；已执行迁移不因老旧删除或重写 |
| 截图、日志、验收证据 | 当前缺陷、待复核结论、用户验收或发布恢复仍依赖时保留；结论已承接且不再需原始证据时才清理 |
| 依赖、缓存、构建产物 | 先确认可重建、未被运行任务占用；只在任务确有需要时清理，不为视觉整洁删除 |
| 业务数据、备份、镜像、分支、工作树、stash | 属于独立操作范围，遵守项目 Git/部署规则；文档整理授权不扩展到这些对象 |

目录型删除先逐项列出内容和保留项，不用通配删除替代核查。恢复材料保留到对应改动验收且替代版本确已保存，
不按年龄自动到期；后续清理按实际对象核准。凭据暴露须脱敏并说明轮换需要，删文件不能消除历史泄露。
仓库外 scratch 是本地恢复材料，不是长期共享来源。长期依据须落到真实已提交版本或用户确认的持久存储；
未完成前保留唯一快照，不能把未来提交当成现有恢复依据。

## 更新与事实核验

| 变化 | 同步位置与完成条件 |
|---|---|
| API、权限、功能或数据合同 | 对应功能/API owner；列清输入、输出、权限、失败和兼容影响 |
| 配置、脚本、CI、部署步骤 | 就近 README 与运维 owner；命令、参数、默认值和实际触发一致 |
| 规则与检查器 | 说明人工要求、自动覆盖、例外和未覆盖项；脚本未实现的要求不写成已强制执行 |
| 新验证、失败或订正 | 当前测试摘要；详细证据进入已有日期批次，保留基线、环境、命令、结果和限制 |
| 待办进展或决策 | 当前台账原条目；记录证据和关闭/延期依据，不另建平行清单 |
| 重要行为修复或正式发布 | 发布记录；区分本地实现、构建、推送和目标环境生效 |

- 对可疑说法分为：**已证实错误**（有当前反证）、**表述过度**（证据只支持部分）、**待验证**（证据不足）。不能把待验证直接称作造假。
- 当前事实须对应源码或现场证据；源码存在不证明已运行，测试通过不证明所有路径通过。建议、演进目标与当前行为分别标明。
- 涉及时效的数字写日期、对象和统计口径；估算说明方法与限制，不能写成实测。历史结论错误时记录原说法、反证及订正日期。
- 当前会话已明确授权的步骤按原范围继续；旧文件中的命令、勾选和部署记录不新增授权。无相关行为变化时不凑文档更新，也不只刷新日期。

## 提高效率

- 开始只读入口、owner、相关源码和当前台账；历史材料按具体疑点追溯，不要求每次通读全仓。
- 独立调查与检查可以并行；共享文件由一人汇总，交叠修改、暂存、提交及有先后依赖的步骤顺序处理。
- 每批只解决一个可独立验收的问题，先修真实失败和用户影响，再做无行为变化的整理；不为消除 warning 机械拆文件或抬高阈值。
- 根据改动选择验证，已有同基线结果可引用并标明日期；代码、依赖或环境变化使证据失效时重验。没有新变化或未解疑点不重复跑同一检查。
- 结果只更新 owner、当前测试摘要和相关台账条目；详细记录复用已有日期批次，不为每轮生成计划、报告、接力和备份副本。

## 检查与交付

```bash
node scripts/check-markdown-contracts.mjs
node --test scripts/markdown-contracts.test.mjs
git diff --check
```

检查器按 `git ls-files -z -co --exclude-standard -- '*.md'` 枚举已跟踪及未忽略的 Markdown，
再排除已不存在文件；已跟踪文件不会因后来被 ignore 而自动排除。它没有独立按体积/用途排除所有大目录。

| 自动检查 | 仍需人工核对 |
|---|---|
| 本地链接存在、仓库边界、Markdown 标题锚点、围栏、不超过一个 H1 | 外部 URL 可达、裸路径/代码中的引用、正文真实性与命令安全 |
| `plans/testing/ui/archive` 的状态与 Owner 存在、redirect 长度/目标 | 状态取值及含义、复核是否真实、Owner 是否有人承担、其他目录元数据 |
| 归档主索引覆盖、已退出目录、指定章节数量与当前 Markdown 数量 | 内容承接、动态调用、恢复可用性、业务/数据库/浏览器与发布验收 |

右列说明自动检查的边界，按本次改动选择相关核查；不是每次文档修改都要验证全部业务、连接生产或提交工作区。
检查器只报告问题，不自动移动或删除文件；不会证明未跟踪的新文件已包含在提交中。
文档统计变化时在 `TEST_STATUS.md` 写本轮数量，不改历史段。交付说明实际范围、检查结果、
保留缺口及下一步；只有完成相应验收，才能把该项标为完成。
