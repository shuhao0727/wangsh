# WangSh 嵌入式页面整理规范

> 状态：active
> Owner：frontend
> 最近复核：2026-10-20
> 参考页面：`/xbk`
> 适用范围：公共页面、后台管理页和数据工作区中的筛选、搜索、页签、表格与操作栏

这份规范总结 `/xbk` 页面当前满意的整理方式。目标是让控件融入所在工作区，形成连续、安静、可扫描的操作界面。后续页面应复用原则和 token，不直接复制页面结构；特殊编辑器、画布和阅读器可以保留自己的专用布局。

## 1. 视觉目标

- 页面首先表现为一个完整的工作区，按钮、筛选、页签和内容围绕同一个任务组织。
- 通过对齐、间距、字号和边界建立层次，减少装饰性卡片、厚重阴影和重复标题。
- 主色只承担主要动作、当前选中状态和必要的焦点提示；次要动作使用低对比度边界。
- 空白区域用于分隔任务，不用来堆叠更多面板或说明文字。
- 页面需要适合连续操作和快速扫描，而不是像宣传页一样强调大标题或视觉装饰。

## 2. 推荐页面骨架

典型数据页面可以采用以下关系：

```text
页面背景
└── 页面内边距
    ├── 筛选列（可选）
    │   └── 筛选行、搜索、重置
    └── 主工作区
        ├── 状态 / KPI / 操作栏
        ├── 页签
        └── 表格与分页
```

### 页面与工作区

- 页面底色使用现有 `--ws-color-bg`，主工作区使用 `--ws-color-surface`。
- 页面内边距优先使用 `--ws-space-2` 到 `--ws-space-3`，主列与筛选列之间使用 `--ws-space-3`。
- 筛选列是任务入口，主工作区是任务主体；两者应有清晰间距，但不需要重复的厚边框。
- 主工作区中的状态栏、页签、工具栏、表格和分页尽量共享同一外框，避免“卡片套卡片”。
- 能用分隔线表达层级时，不再增加新的卡片容器或阴影。

### 筛选列宽度

- 桌面端筛选列以约 `220px` 为起点，再根据最长标签和控件内容调整。
- 宽度的判断标准是：`全部年级`、`全部班级`、完整学年值和搜索占位文本都能自然显示。
- 不为了追求多列而压缩控件；当文字开始省略或下拉箭头挤压内容时，应优先恢复宽度。

## 3. 筛选区整理规则

### 标题与信息层级

- 当筛选列已经位于明确的筛选工作区中，删除重复的“筛选条件”标题。
- 保留必要的字段标签，例如“学年”“学期”“年级”“班级”“搜索”。
- 标签只说明控件含义，不写成解释性句子，也不重复当前值。

### 标签与控件

推荐使用“短标签 + 完整控件”的横向行：

```css
grid-template-columns: 36px minmax(0, 1fr);
```

- 标签列保持稳定宽度，控件列占据剩余空间。
- 标签使用 `--ws-text-xs`，颜色使用 `--ws-color-text-secondary`。
- 控件使用统一的 `--ws-control-height`，当前 token 为 `36px`。
- 控件字号以 `--ws-text-xs` 或 `--ws-text-sm` 为准；需要容纳较长值时优先增加宽度，不要继续缩小字号。
- 下拉框、输入框和相关按钮应共享高度、圆角和边框语义。

### 搜索框

- 搜索框单独占满控件列，不与多个短控件挤在同一行。
- 左侧图标固定在输入区域内，使用 `--ws-search-input-padding-start` 预留文本空间。
- 搜索图标只做识别提示，不替代可访问名称；输入仍应提供 `aria-label` 或关联标签。
- 占位文本简短，说明可以搜索的对象，不写成长说明。

### 重置操作

- 重置按钮放在筛选字段之后，与控件列对齐。
- 用 `border-top: 1px solid var(--ws-color-border-secondary)` 做轻分隔。
- 重置属于次要操作，优先使用 `ghost` 或低强调样式；不要与主提交按钮竞争视觉重量。

### 不采用的布局

- 不把四个筛选控件强行排成双列，除非每个控件都能保持足够宽度。
- 不使用标签在上、控件在下的长列表作为默认方案；它会拉高筛选列并造成右侧工作区视觉失衡。
- 不给每个字段单独加卡片、阴影或厚边框。

## 4. 按钮与操作栏

- 每个操作栏只保留一个最主要的视觉动作，使用项目主色按钮。
- 导出、分析、刷新等次要动作使用 `outline` 或 `ghost`；删除使用已有危险语义。
- 适合工具栏的按钮高度约 `32px`，普通表单按钮使用 `--ws-control-height`，大型确认动作才使用大尺寸。
- 图标使用已有 lucide 图标，图标与文字间距保持一致；图标按钮必须有 `aria-label` 或 `title`。
- 按钮文字应完整落在按钮内。文字较长时优先调整按钮组换行和容器宽度，不要让多个按钮压缩成难以识别的窄条。
- 相关动作按任务分组，组间使用间距或细分隔线；不要让所有动作混成一排没有层次的按钮。
- 搜索/筛选与刷新/管理/新建等动作应分别包在稳定的分组容器中；窄屏在组级换行，不要依赖一个裸 `flex-1` 占位元素控制换行。

## 5. 页签、表格与分页

- 页签属于主工作区的一部分，不再包裹一层独立卡片。
- 当前页签使用主色文字和底部细选中线，非当前页签使用次级文字颜色。
- 表头使用轻微的工作区底色和 `1px` 底边框，避免高饱和色块。
- 表格正文使用 `--ws-text-sm`，行高和上下内边距保持一致；列内容较长时使用省略号，但不能遮挡关键身份字段。
- 空表是工作区状态，空状态在表格主体中居中显示，不使用整行强烈底色或额外提示卡片。
- 分页与表格共享底部边界，使用轻分隔线和紧凑间距。

## 6. 色彩、边框与阴影

- 所有颜色使用 `--ws-*` 语义 token 或对应 Tailwind token，不在页面 CSS 中新增硬编码色值。
- 普通控件：`--ws-color-surface` 背景、`--ws-color-border-secondary` 边框。
- 悬停状态：提高边框对比度即可，不要突然增加阴影或改变大面积背景。
- 聚焦状态：保留全局焦点环和主色边界，确保键盘操作可见。
- 常规工作区优先无阴影或极轻阴影；阴影只用于真正浮起的菜单、弹窗和浮动面板。
- 圆角使用 `--ws-radius-sm`、`--ws-radius-md`、`--ws-radius-lg`，同一层级不要混用过多圆角档位。

## 7. 字号与间距基准

| 用途 | 推荐 token | 说明 |
|---|---|---|
| 字段标签、辅助文字 | `--ws-text-xs` | 简短、低强调，不承担主要信息 |
| 控件、表格正文、普通按钮 | `--ws-text-sm` 或 `--ws-text-xs` | 以完整显示内容为优先 |
| 工作区标题、关键数值 | `--ws-text-md` 到 `--ws-text-lg` | 只用于需要被快速扫描的内容 |
| 字段之间 | `--ws-space-2` | 保持连续但不拥挤 |
| 页面区域之间 | `--ws-space-3` | 区分筛选列和主工作区 |
| 细分隔区域 | `--ws-space-1` 到 `--ws-space-2` | 不制造过大的空洞 |

不要为了“高级感”缩小所有字号，也不要用大量不一致的局部像素值覆盖 token。先统一高度和间距，再判断是否需要页面特例。

## 8. 响应式要求

- 优先验证 `1280x800`、`1440x900`、`1680x1050` 和 `1920x1080` 桌面尺寸。
- `768px` 左右可以将筛选列移到主工作区上方，筛选列宽度改为 `100%`。
- 更窄屏幕下，控件可以恢复纵向排列，但标签和输入内容仍必须完整可读。
- KPI 或操作按钮允许换行、分组或变成网格，不允许出现左侧拥挤、右侧大面积空置的失衡布局。
- 表格可以在自身容器内横向滚动，但表头、分页和空状态不能被裁切；不要通过整体缩放页面来解决宽表问题。
- 宽表最小宽度应施加在实际 `<table>` 上，并由其 `overflow-x: auto` 容器承载滚动；只给外层包裹设置最小宽度不能阻止列被压缩。还需检查全局响应式规则是否把表格 `min-width` 重置为 `0`。

## 9. 交互与可访问性

- 每个下拉框、搜索框和操作按钮都提供稳定的 `id`、`aria-label` 或可关联标签。
- 视觉上的图标不能成为唯一的操作说明；图标按钮要有名称或原生 `title`。
- 保留键盘焦点样式，不能用 `outline: none` 隐藏焦点而没有替代反馈。
- 下拉菜单选项高度应与普通控件和文字密度协调，避免选项远高于触发器。
- 加载、错误、空数据和重试状态必须在原工作区内表达，不能用“空白页面”伪装成功。

## 10. 整理页面前检查清单

- [ ] 页面是否有重复标题或解释文字，可以删掉吗？
- [ ] 筛选标签和控件是否同一基线对齐？
- [ ] 最长选项和搜索占位文本是否完整显示？
- [ ] 所有控件高度、字号、圆角和边框是否统一？
- [ ] 主按钮是否只有一个清晰的视觉重点？
- [ ] 页签、工具栏、表格是否属于同一个工作区？
- [ ] 是否存在卡片套卡片、厚阴影或无意义边框？
- [ ] 空状态、加载状态、错误状态和重试操作是否可见？
- [ ] 桌面端和窄屏端是否分别检查过？
- [ ] 是否使用了现有 `--ws-*` token，而不是新造颜色和尺寸？

## 11. 数据工作区复盘规则

本节记录 `/admin/agent-data` 本轮整理后确认的细节，适用于后续列表、统计和筛选页面。

### 统计摘要

- 核心数量和辅助时间指标分组表达。核心数量优先使用中等字号和稳定行高，时间范围、平均响应等指标降低字号和对比度。
- 标签与数值保持紧凑的同行关系，不使用过大的数字、等宽铺满或逐项竖线制造层级。
- 统计摘要、页签和必要的工作区入口可以共用同一条顶栏；不要为每组指标再套一层卡片。
- 主色只强调最重要的一个指标或当前状态，其余指标用中性文字保持连续阅读。

### 结果区与操作占位

- 结果区只显示当前有意义的操作。空数据时不要显示“共 0 条记录”、禁用的导出按钮或为了对齐而保留的空操作栏。
- 真实数据总数优先由分页表达；只有存在选中记录时，才显示紧凑的导出操作。
- 表头、空状态和内容区保持连续；空状态属于表格工作区，不额外包裹成提示卡片。
- 不用表格的最小宽度把空状态推到窄屏视口外。宽表需要内部横向滚动，表头和空状态仍要可见。

### 尺寸与排版复核

- 先检查控件的实际宽高、基线、间距和容器边界，再决定是否改字号或布局；不能只看颜色和圆角。
- 普通筛选控件维持约 `36px`，工具栏动作约 `32px`，紧凑图标动作和菜单项约 `28px`。同一操作组不要混用明显不同的高度。
- 下拉选项的行高应接近触发器和正文密度；选项明显高于触发器时，即使功能正常也会破坏嵌入感。
- 每一档桌面宽度都要检查左侧是否拥挤、右侧是否空置，以及操作是否被挤到第三行；窄屏再检查文字裁切、横向溢出和菜单边界。

### 状态与证据

- 至少检查加载、错误、空数据和有数据四种状态；接口为空时不能把“空状态通过”当成真实数据流程通过。
- 查询、重置、页签、下拉 Escape、分页、行选择和导出等操作要记录真实交互结果；未覆盖的业务流明确写出。
- 页面确认前只更新当前页面记录；用户确认后再把页面标记为已完成并进入下一页，避免路线图状态提前推进。

- 页面样式：`frontend/src/pages/Xbk/Xbk.css`

## 13. 编辑器和设置页补充规则

- 编辑器只保留一套返回与工作区标题。宿主布局有顶栏时，页面内部不要再重复相同导航；独立学习编辑器由自己的工具栏负责返回正确管理入口。
- 章节目录只出现一次。编辑预览复用正文渲染器时关闭阅读器自带目录，编辑、分屏与预览应显示当前编辑副本。
- 桌面分屏必须检查两块内容的实际宽高，不能只设置 `w-1/2` 却仍按纵向排列；编辑区容器也应填满剩余高度。
- 侧栏和元数据面板独立滚动。窄屏可以改为上下布局或章节选择器，不能直接隐藏唯一的内容切换入口。
- 某种模式在窄屏不可用时，同时修正当前模式和高亮状态。例如隐藏“分屏”按钮时，不能让正文仍停留在隐性的分屏状态。
- 搜索、分类等控制区域放在数据状态分支之外，空数据、筛选无结果或加载失败时仍需可操作。
- 只读系统配置用对齐字段表达；可编辑设置才使用输入框。应用入口按任务选择卡片或条目，不把“嵌入式”机械理解为取消卡片。
- `/admin/it-technology` 采用无边框的嵌入式紧凑卡片：不设外框、阴影、底栏分割线或独立底色，图标、名称和操作直接融入页面，悬停与键盘焦点保留轻量提示。应用按组展示，分类只出现在组标题；“公开课”依次放“召唤一名AI同学”“密码锁破解”“KNN 运动习惯采集”，卡片内不重复分类或常驻功能说明。正文内边距约 12px、图标约 32px，标题使用 `--ws-text-md`，开关和管理动作在名称下方对齐。宽工作区四列，随可用宽度逐步减为三列、两列和单列；应用较少时不拉伸卡片铺满整行。原有带框卡片已被本次明确反馈替代，当前效果已获用户确认；其他页面仍按各自任务选择布局。
- 不把 `h-8` 等 rem 类名直接当作固定像素验收。当前根字号会随视口变化，关键高度优先采用现有尺寸 token，并量测实际控件高度。
- 编辑器可能自动保存、编译或初始化数据；视觉检查前先查清请求时机，不用创建真实数据来凑足页面状态。隔离请求或缺少内容时，明确记录验收边界。
